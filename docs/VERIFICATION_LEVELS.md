# 待轉格圖資的查證等級制度

每一筆資訊帶一個查證等級，記錄「這件事是**怎麼**被確認的」。
目的不是給資料貼標籤好看，而是讓 App 能依等級決定**敢說什麼話**。

---

## 1. 先確定「一筆資訊」是什麼

不是「一個待轉格」。

待轉格不是路線經過的東西，是**服務某一個進入方向**的設施。騎士要問的是
「我從這個方向進來要左轉，該靠左還是靠右」，所以查證的單位是**路口 × 進入方位**。

```
claim_id = <intersection_id>/<approach_bearing>
           ix_wsqmcs47/090          從東邊進來(方位 90°)要左轉的那個 claim
```

一個路口通常有 3–4 個進入方向，各自獨立查證。同一個路口可能東向已經實地確認、
北向還只有影像辨識——這很正常，也正是分等級的意義。

待轉格本身（`dt_` 那些多邊形）是 claim 的**證據**，不是 claim 本身。

### 兩種 claim，代價完全不對稱

| claim | 說錯的代價 |
|---|---|
| **exists**「這裡要待轉」 | 多等一個燈 |
| **absent**「這裡可以直接左轉」 | **罰單**，加上在內側車道左轉遇到直行車的風險 |

這個不對稱決定了整套制度的設計：**兩種 claim 要用不同的等級門檻。**
現在 App 的 `direct` 狀態是從「模型沒找到框」推出來的——
也就是說，**最危險的那個判斷，目前的證據等級是「機器的沉默」**。
這是整個設計要補的最大破口。

---

## 2. 等級定義

| 等級 | 名稱 | 證據 | 誰產生 |
|---|---|---|---|
| **L0** | 未勘查 | 沒有可用影像，或影像取得失敗／被雲遮 | — |
| **L1** | 影像辨識 | 模型在正射影像上的判讀 | `model:dieturn-v0.5` |
| **L2** | 人工影像複核 | 人看著影像確認 | `human:<複核者>` |
| **L3** | 實地確認 | 現場或街景層級影像確認 | `field:<場次>` |

L0 是預設值，不是失敗狀態。「我們沒看過」和「我們看過但沒有」是兩件完全不同的事，
這個區別已經是現有 App 的核心（`surveyed_intersections` 就是為了這個存在），
等級制度只是把它講得更清楚。

### 兩個不另設等級的東西

**官方清冊**（交通局／公路局的待轉路口資料）→ 當作 **L2 的一種 actor**，
`actor: "authority:新北市交通局_2026Q1"`。理由：官方資料一樣會過期、一樣可能不完整，
可靠度接近人工複核，不到實地確認。給它一個獨立的高等級會高估它。

**群眾回報** → **不直接給等級**，當作「觸發複核的訊號」。
一個未受訓的用路人回報不等於複核。但同一個 claim 累積 3 筆以上一致的回報，
就自動排進 L2 佇列的最前面。回報本身記在證據鏈裡，只是不單獨支撐判定。

### 等級 ≠ 信心值

信心是**同一種證據內部的強弱**，等級是**證據的種類**。
一個 conf 0.98 和一個 conf 0.55 的模型偵測都是 L1。兩個欄位要分開存，
合併成一個分數會把資訊壓掉——之後想改門檻就沒得改了。

---

## 3. 資料結構：證據鏈 + 推導狀態

分成兩層。**證據只增不改**，狀態隨時可以用新政策重新推導一次。

### 3.1 證據紀錄（append-only）

```jsonc
{
  "obs_id": "ob_01JQ...",                    // ULID，時序可排
  "claim_id": "ix_wsqmcs47/090",
  "verdict": "exists",                        // exists | absent | unclear
  "level": 1,
  "confidence": 0.867,                        // L1=模型信心；L2/L3=觀察者自評 0–1
  "zone_id": "dt_wsqmcs47xk",                 // verdict=exists 時指向哪個框
  "actor": "model:dieturn-yolo26s-obb-v0.5",
  "evidence": {
    "imagery": "nlsc_photo2025",
    "imagery_zoom": 20,
    "captured_year": 2025,
    "image_id": "ix_wsqmcs47",
    "src_px": "412.3,388.1;456.0,391.2;...",  // 可回溯到原圖像素
    "photo_ref": null                          // L3 放現場照
  },
  "quality": {
    "shadow": 0.4,                             // 路口區域陰影覆蓋比例
    "occluded": false,                         // 樹冠／建物遮蔽
    "usable": true
  },
  "observed_at": "2026-09-08T14:51:00Z",
  "note": ""
}
```

`evidence` 和 `quality` 是這個設計的重點。**沒有它們，等級只是個標籤。**
有了它們，你可以事後問「所有在陰影下做出的 absent 判定，實地確認的正確率是多少」——
這種問題才是讓制度持續改善的東西。

### 3.2 推導狀態（每個 claim 一筆，可重算）

```jsonc
{
  "claim_id": "ix_wsqmcs47/090",
  "verdict": "exists",
  "level": 2,                        // 支持現行判定的最高等級
  "supporting": ["ob_01JQ...", "ob_01JR..."],
  "conflict": false,                 // 不同等級之間是否矛盾
  "conflict_detail": null,
  "last_verified": "2026-10-02",
  "imagery_year": 2025,
  "app_status": "required",          // 由第 4 節的政策表決定
  "policy_version": "v1"
}
```

### 3.3 三條推導規則

1. **高等級覆蓋低等級。** L3 說沒有，L1 說有 → verdict = absent，並標 `conflict: true`。
2. **矛盾要保留，不要吞掉。** 模型與人工不一致的案例是最有價值的訓練訊號，
   它們會聚集在模型的系統性弱點上（目前看來是陰影）。
3. **同等級內取最新。** 影像會更新，標線會重畫。

---

## 4. 等級 → App 敢說什麼

這張表是整套制度的產出。其他都是為了填滿它。

| verdict | 影像層級 | 影像品質 | 最低等級 | App 顯示 |
|---|---|---|---|---|
| **exists** | 任何 | 任何 | **L1** | `required`（靠右待轉） |
| **absent** | z21（recall 已量測） | 清晰 | **L1** | `direct`（可直接左轉） |
| **absent** | z20 | 清晰 | **L1**，且該影像層級的 recall ≥ 門檻 | `direct` |
| **absent** | z20 | 陰影／遮蔽 | **L2** | 未達則 `unknown` |
| **absent** | 任何 | 任何 | **L2 / L3** | `direct` |
| — | 無影像 | — | **L0** | `unknown` |

三個要點：

**exists 只要 L1 就直接用**，連低信心的也用。方向是保守的——多叫他待轉一次不會出事。

**absent 的門檻綁在「那批影像量測過的 recall」上**，不是綁在等級數字上。
這讓政策有依據：如果 Phase 0 量出 z20 的 recall 是 0.85，模型的沉默就有 85% 的可信度；
如果是 0.5，那沉默幾乎沒有意義，z20 區域的 absent 就該一律降級成 `unknown`。

**影像品質是獨立的降級條件。** 100 張新北 z20 的抽測顯示，低信心偵測幾乎全部落在
樹影和建物陰影裡——這是模型已知的弱點。所以**在陰影下做出的 absent，可信度顯著低於
在清晰影像下做出的 absent**，即使兩者都是 L1。這一條可以自動判定，不需要人力。

---

## 5. 升級流程：人力要花在哪

30,000 個路口 × 約 3.5 個方向 ≈ **10 萬個 claim**。全部人工複核不可能，
所以制度的真正價值在於**決定先看哪些**。

### L1 → L2 的優先序（依期望價值排序）

1. **清晰影像下的 absent，且該路口很大**（`n_nodes ≥ 4`）。
   大路口一定有號誌、多半有待轉規定，模型在這裡沉默最可疑，說錯代價也最大。
2. **陰影／遮蔽下的 absent。** 政策上已經降級成 `unknown`，複核能把它救回 `direct`，
   直接提升可用覆蓋率。
3. **conf 0.5–0.8 的 exists。** 就是現在 `review.csv` 在做的事。
4. **尺寸異常的 exists。** 抽測看到 6.3 × 3.5 m 的框，多半是機車停等區誤判。
   基準是台北的 4.85 × 2.53 m；長邊 3–6 m、短邊 1.8–3.5 m 之外的先送複核。
5. **群眾回報累積 ≥ 3 筆的 claim。**

### L2 的作業方式

`apps/map-viewer/` 現在只能看。要加一個複核模式：讀佇列、逐筆把框疊在底圖上、
鍵盤 accept / reject / unclear、寫回一筆證據紀錄。
**每一次按鍵都是一筆 append-only 的 observation，不是就地改資料。**

同一批抽 5% 重複派給第二個人，用一致率當品質控制——這個數字本身也要記下來，
因為它是 L2 這個等級「值多少」的實測值。

### L3 要做在哪

實地確認貴，只做兩件事：

1. **校準 L1 和 L2。** 每個縣市抽 20–30 個 claim 實地確認，得到
   「L1 說 absent 時實際正確率是多少」——這個數字直接餵回第 4 節的政策表。
   **L3 的主要用途是量測其他等級的可信度，不是把資料一筆一筆升級。**
2. **處理爭議。** 群眾回報和 L2 矛盾、或 L2 兩人不一致的案例。

街景層級影像可以當作 L3 的一種（`actor: "field:streetview"`），
但要記清楚拍攝日期，而且**不要用別家地圖的圖去標註**——這是資料授權問題，
專案的標註規範已經寫過。

---

## 6. 時效

影像有年份，標線會重畫，路口會改建。

- 每筆狀態帶 `imagery_year` 與 `last_verified`。
- **不自動降級**，但超過 N 年（建議 4 年）的 claim 在複核佇列裡加權。
- NLSC 有 `PHOTO2014`–`PHOTO2025` 的完整年度層。**同一個路口跨年度各跑一次推論，
  結果不一致就是「這裡改過」的訊號**——這是免費的變更偵測，值得做。

---

## 7. 要動到的既有欄位

現有的 `status: auto|review` 與 `confidence: confirmed|probable` 是這套制度的雛形，
但它們把「證據種類」和「證據強度」壓在同一個欄位裡，而且只描述 exists、
完全沒有描述 absent。建議：

| 現況 | 改成 |
|---|---|
| `status: "auto"` | `level: 1` + `confidence: 0.93` |
| `status: "review"` | `level: 1` + `confidence: 0.62` + 進 L2 佇列 |
| `confidence: "confirmed"` | 由 `level` 與 `confidence` 推導，不再獨立存 |
| （無對應）| `verdict: exists\|absent\|unclear` ← 新增，absent 是全新的一類 |
| （無對應）| `quality: {shadow, occluded}` ← 新增 |

改欄位要同步三處（repo 的 `CLAUDE.md` 有記載這個地雷）：
`geodata/build_geodata.py` 的 `props`、`geodata/export_app.py` 的 `KEEP`、
`apps/howtoturn/src/lib/types.ts` 的 `WaitingZoneProps`。沒有 codegen，漏掉不會編譯錯。

App 端 `lib/twoStageLeft.ts` 現在是從「有沒有找到框」直接推 `direct`/`unknown`。
改成讀 claim 的 `app_status`，判斷邏輯就從前端搬到離線管線——
**這也讓安全政策變成一個可以審閱、可以版本控制的檔案，而不是散在前端的 if。**

---

## 8. 落地順序

1. 先把 `verdict` 和 `quality` 加進離線管線——**absent 要變成一個真的會被寫出來的東西**，
   不是前端從沉默推論出來的。
2. Phase 0 量出 z20 的 recall，填進第 4 節的政策表。
3. 做 L2 複核介面，用第 5 節的優先序跑第一批 500 筆。
4. 用第一批 L2 結果反推「L1-absent 的正確率」，校準政策。
5. L3 抽樣校準，每縣市 20–30 筆。

第 1 步和第 2 步之前，不要開始大規模人工複核——沒有政策表，複核的結果無處可去。
